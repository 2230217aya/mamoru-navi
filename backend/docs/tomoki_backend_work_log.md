# バックエンド担当作業メモ

## 概要

まもるナビのバックエンド開発において、自分が担当した作業内容をまとめる。

バックエンドは複数人で担当しているため、このドキュメントでは自分が主に実装・修正・整理した内容を記録する。

---

## 担当した主な作業

### 現在地登録APIの実装・調整

ユーザーID、緯度、経度を受け取り、`user_locations` テーブルに位置情報を保存するAPIの実装・調整を行った。

対象API：

```txt
POST /locations/
```

---

### 最新位置情報取得APIの実装・調整

指定したユーザーIDの最新の位置情報を取得するAPIを実装・調整した。

対象API：

```txt
GET /locations/{user_id}/latest
```

---

### 避難所エリア判定APIの実装・修正

ユーザーの現在地と避難所の距離を計算し、避難所エリア内にいるかどうかを判定するAPIを実装・修正した。

PostGISの `ST_Distance` や `ST_DWithin` を使用し、避難所から500m以内かどうかを判定するようにした。

対象API：

```txt
GET /locations/{user_id}/area
```

---

### 避難所ごとの人数集計APIの実装

避難所ごとに、エリア内にいるユーザー数を集計するAPIを実装した。

同一ユーザーの位置情報が複数ある場合は最新の位置情報のみを使用し、古い位置情報を混雑判定に含めないようにした。

対象API：

```txt
GET /shelters/crowd-counts
```

---

### 混雑度変換処理の実装・修正

現在人数と収容人数から混雑率を計算し、混雑度を判定する処理を実装した。

また、`capacity` が `0` または未設定の場合でもエラーにならないよう、`crowd_rate` を `null`、`crowd_level` を `unknown` として返すように修正した。

---

### ヒートマップ用データ取得APIの実装

フロントエンドでヒートマップ表示に使用するため、避難所ごとの緯度・経度、現在人数、混雑率、混雑度を返すAPIを実装した。

対象API：

```txt
GET /shelters/heatmap
```

---

### オフライン地図用データ取得APIの実装・改善

オフライン時に使用する避難所データを取得するAPIを実装した。

また、フロントエンド側で取得件数を確認しやすくするため、レスポンスに `count` を追加した。

対象API：

```txt
GET /offline/map-data
```

---

### ヘルスチェックAPIの追加

Docker起動後やフロントエンドとの結合時に、バックエンドが正常に起動しているか確認するためのAPIを追加した。

対象API：

```txt
GET /health
```

---

### API仕様書の作成・更新

バックエンドAPIのエンドポイント、概要、リクエスト例、レスポンス例をまとめた仕様書を作成・更新した。

対象ファイル：

```txt
backend/docs/api_spec.md
```

---

### 混雑度関連仕様書の作成

混雑判定の単位や、混雑度の判定基準を整理するための仕様書を作成した。

対象ファイル：

```txt
backend/docs/crowd_unit_policy.md
backend/docs/crowd_level_policy.md
```

---

### 開発用避難所初期データSQLの追加

開発環境で避難所データを確認しやすくするため、テスト用の避難所初期データを投入するSQLを追加した。

対象ファイル：

```txt
backend/sql/seed_shelters.sql
```

---

## 工夫した点

- PostGISを使用して、ユーザーの現在地と避難所の距離をメートル単位で判定できるようにした
- 混雑判定では、5分以内の最新位置情報のみを対象にして、古い情報を集計しないようにした
- 同一ユーザーの位置情報が複数ある場合でも、最新の1件だけを使用するようにした
- `capacity` が `0` または未設定の場合でも、APIがエラーにならないようにした
- フロントエンドで扱いやすいように、APIレスポンス形式を整理した
- Swagger UIで各APIの動作確認を行いながら実装を進めた

---

## 今後確認したいこと

- フロントエンドとの結合時に、各APIのレスポンス形式が使いやすいか確認する
- オフライン地図用データに追加で必要な項目がないか確認する
- 混雑度やヒートマップ表示が、フロントエンド上で想定通りに表示されるか確認する
- 発表時に、PostGISを使った距離判定や混雑度判定の仕組みを説明できるようにする
