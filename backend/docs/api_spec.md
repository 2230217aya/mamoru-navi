# バックエンドAPI仕様書

## 概要

このドキュメントでは、まもるナビで使用するバックエンドAPIの仕様をまとめる。

バックエンドでは、主に以下の機能を提供する。

- ユーザーの現在地登録
- ユーザーの最新位置情報取得
- 避難所情報取得
- 避難所エリア判定
- 避難所ごとの人数集計
- 混雑度取得
- ヒートマップ用データ取得
- オフライン地図用データ取得
- 古い位置情報の削除

---

## 1. 現在地登録API

### エンドポイント

```txt
POST /locations/
```

### 概要

ユーザーの現在地情報を登録する。
ユーザーID、緯度、経度を受け取り、`user_locations` テーブルに保存する。

### リクエスト例

```json
{
  "user_id": "11111111-1111-1111-1111-111111111111",
  "latitude": 34.6937,
  "longitude": 135.5023
}
```

### レスポンス例

```json
{
  "message": "位置情報を受け取りました",
  "id": "026ef28b-1388-4a05-be97-4c9d0fdd9042",
  "user_id": "11111111-1111-1111-1111-111111111111",
  "latitude": 34.6937,
  "longitude": 135.5023,
  "recorded_at": "2026-06-01T05:03:14.000000"
}
```

## 2. 最新現在地取得API

### エンドポイント

```txt
GET /locations/{user_id}/latest
```

### 概要

指定したユーザーの最新の位置情報を取得する。
同じユーザーが複数回位置情報を送信している場合でも、最新の1件のみを返す。

### パスパラメータ

| パラメータ | 型     | 説明       |
| ---------- | ------ | ---------- |
| user_id    | string | ユーザーID |

### レスポンス例

```json
{
  "id": "026ef28b-1388-4a05-be97-4c9d0fdd9042",
  "user_id": "11111111-1111-1111-1111-111111111111",
  "latitude": 34.6937,
  "longitude": 135.5023,
  "recorded_at": "2026-06-01T05:03:14.000000"
}
```

## 3. 避難所一覧取得API

### エンドポイント

```txt
GET /shelters
```

避難所ID、避難所名、住所、緯度、経度、収容人数を返す。

```json
      "longitude": 135.5023,
      "capacity": 100

  ]
}
```

## 4. 避難所エリア判定API

### エンドポイント

```txt
GET /locations/{user_id}/area
```

### 概要

指定したユーザーの現在地が、避難所エリア内にいるかどうかを判定する。
避難所との距離を計算し、500m以内であれば `in_area` を `true` として返す。

### パスパラメータ

| パラメータ | 型     | 説明       |
| ---------- | ------ | ---------- |
| user_id    | string | ユーザーID |

### レスポンス例

```json
{
  "user_id": "11111111-1111-1111-1111-111111111111",
  "shelter_id": "ebc1b1f7-b871-48d1-b551-69dba90129a5",
  "shelter_name": "テスト避難所",
  "distance_m": 0,
  "area_radius_m": 500,
  "in_area": true
}
```

## 5. 避難所ごとの人数集計API

### エンドポイント

```txt
GET /shelters/crowd-counts
```

### 概要

避難所ごとに、避難所エリア内にいるユーザー数を集計する。
混雑判定では、最終更新から5分以内の位置情報のみを対象とする。
同一ユーザーの位置情報が複数存在する場合は、最新の位置情報のみを使用する。

### レスポンス例

```json
{
  "crowd_counts": [
    {
      "shelter_id": "ebc1b1f7-b871-48d1-b551-69dba90129a5",
      "shelter_name": "テスト避難所",
      "capacity": 100,
      "current_user_count": 1,
      "crowd_rate": 0.01,
      "crowd_level": "空きあり"
    }
  ]
}
```

## 8. 古い位置情報削除API

### エンドポイント

```txt
DELETE /locations/old
```

### 概要

最終更新から一定時間以上経過した古い位置情報を削除する。
現在の仕様では、最終更新から5分以上経過した位置情報を古い情報として扱う。

### レスポンス例

```json
{
  "message": "古い位置情報を削除しました",
  "deleted_count": 3,
  "stale_minutes": 5
}
```

## 補足

### 位置情報の扱い

ユーザーの位置情報は、PostGISのPoint型として保存する。

距離計算では、`ST_DWithin` や `ST_Distance` を使用する。
メートル単位で距離を扱うために、必要に応じて `geography` 型へ変換して計算する。

### 混雑度の基準

混雑度は、現在人数と収容人数から算出した混雑率をもとに判定する。

| 混雑率     | 表示     |
| ---------- | -------- |
| 0% 〜 49%  | 空きあり |
| 50% 〜 79% | やや混雑 |
| 80% 〜 99% | 混雑     |
| 100%以上   | 満員     |

| 条件                       | crowd_rate | crowd_level |
| -------------------------- | ---------- | ----------- |
| capacity が 0 または未設定 | null       | unknown     |

- `crowd_unit_policy.md`：混雑判定の単位に関する仕様
- `crowd_level_policy.md`：混雑度の判定基準に関する仕様

### QRコードおよびユーザー識別のルール

- **QRコードのフォーマット**:
  - `mamoru_navi_user:UUID` という接頭辞（Prefix）を必須とする。
  - 接頭辞がない文字列をスキャンした場合は、API側で `400 Bad Request` を返却し、不正なコードとして扱う。
- **IDスキャンのシミュレーション**:
  - `/scan/id-card` APIは、現在OCRエンジンの代わりに固定の `extracted_name` を使用して検索を行っている。本格稼働時は、信頼スコア（Confidence Score）に基づく判定ロジックを導入予定。

### 住民情報の秘匿基準

避難所（災害時）と公共施設（平常時）では、APIが返却する情報のスコープを以下のように制御する。

| 取得モード (`scan_mode`) | 氏名・連絡先 | 血液型・持病 | 理由                                       |
| ------------------------ | ------------ | ------------ | ------------------------------------------ |
| `facility` (平常時)      | 表示         | **非表示**   | プライバシー保護のため最低限の情報のみ公開 |
| `shelter` (災害時)       | 表示         | **表示**     | 迅速な救護およびトリアージに活用するため   |

### オフライン同期と不整合の防止

- **冪等性（べきとうせい）の確保**:
  - `checkins` テーブルへの登録時、`user_id` + `shelter_id` + `DATE(checkin_time)` が重複する場合、バックエンドは既存レコードの更新、またはエラーをスキップし、重複登録を防止する。
- **同期順序**:
  - `sync_queue` からの同期は、`created_at` の昇順に行われることを前提とする。

### 差分ダウンロードの仕組み (`updated_at` 制御)

- `/scan/users/download` における差分取得の基準。
  - フロントエンドは、ローカルDB内の `MAX(updated_at)` を `updated_at` パラメータとして送信する。
  - バックエンドは `updated_at > パラメータ値` のレコードを返却する。
  - これにより、通信量を最小限に抑えつつ、住民の最新情報（持病の更新など）を職員端末に反映させる。
